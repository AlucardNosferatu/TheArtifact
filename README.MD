战区88风格佣兵空战模拟｜RPG Maker MV 项目 README
 
一、项目定位
 
这不是传统冒险RPG，也不做复杂数值战斗、开放地图，而是以《战区88》为原型的「基地箱庭+每周空战任务+战斗剧情演出」模拟游戏。
核心：扮演战区88的佣兵，在单一基地里熬过3年，每周执行1次空战任务，用战斗事件做戏剧性，还原原作紧张、悲壮的空战氛围。
 
二、核心玩法循环（唯一流程，不跑偏）
 
1. 玩家仅在基地88这一张箱庭地图内活动（指挥塔、停机坪、机库、简易休息区）；
2. 走到停机坪 → 触发事件：「是否执行本周出勤任务？」；
3. 确认后直接进入固定配置的战斗，无额外地图、无复杂过渡；
4. 战斗内通过预设事件完成剧情演出，结束后返回基地，时间推进1周；
5. 循环至3年任务全部完成。
 
三、核心规则（定死，不改动）
 
- 总周期：3年
- 任务频率：每周出动1次
- 总任务次数：156次
- 所有任务敌群完全固定，不随机、不动态生成；
- 战斗不追求数值平衡，只追求空战戏剧性、剧情感。
 
四、战斗设计核心（重点）
 
1. 抛弃复杂技能、装备、数值平衡，不做“好玩耐玩”，只做“有戏、有味道”；
2. 全程使用RM MV 原生战斗事件实现演出：
- 回合触发：增援、警告、友机支援
- 血量触发：敌机暴走、求饶、剧情杀
- 击败触发：台词、退场、剧情反转
3. 每场战斗只做2～3个小事件，还原《战区88》经典场景：伏击、救援、王牌登场、燃油告警、紧急返航等。
 
五、数据开发流程（利用RM MV JSON优势）
 
1. 打开RM编辑器前，先用Excel整理好：战机、敌机、技能、任务基础数据；
2. 配合AI生成/整理，直接输出符合RM MV格式的JSON数据库文件；
3. 批量导入，减少手动填表，大幅提升效率。
 
六、GitHub 存储规范（防止遗忘、体积过大）
 
1. 代码/文本/配置文件：直接上传，Git自动压缩；
2. 图片文件夹  img ：压缩为 img.zip 上传，删除原文件夹；
3. 根目录保留说明：下载后解压  img.zip  还原为  img  即可打开项目；
4. 多分支管理：每个分支为独立原型，命名清晰，统一这套规范。
 
七、开发底线（防止烂尾、反复重写）
 
- 只做1张地图：基地88，不扩展任何新场景；
- 只做核心循环：基地→停机坪→战斗→回基地；
- 不优化UI、不写复杂插件、不追求完美；
- 能跑通156次任务逻辑 + 战斗事件演出 = 项目完成。
 
八、项目预期目标
 
做出一个完整、能通关、有《战区88》内味儿的空战佣兵模拟：
 
- 流程极简，不折腾复杂系统；
- 战斗像“空战小剧场”，而非纯数值对轰；
- 以后打开工程，看这份文档就能立刻续开发，不会断思路、不会从头重做。
